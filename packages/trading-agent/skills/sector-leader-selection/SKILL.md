# 板块龙头选择技能

## 功能概述

本技能用于从指定行业、子行业或概念板块中，通过多维度指标对比和两两淘汰，筛选出板块龙头。筛选结果可保存为新的股票池，供后续回测或跟踪使用。

## 使用场景

当用户请求以下操作时触发本技能：
- "选出白酒板块的龙头"
- "半导体概念龙头股有哪些"
- "帮我筛选汽车行业的龙头企业"
- "对某个股票池按行业分组，每组选龙头"
- "选出最近热门概念的龙头股"

## 输入模式

### 模式一：直接查询问财 + 精选（推荐，最简洁高效）

优先使用 `iwencai_screen` 直接对板块做龙头股初筛，然后在返回结果上做精选。

**核心思路**：
1. 用问财自然语言一次性完成成分股范围、市值排序、资金排序、动量排序。
2. 取问财返回的前 **30只** 作为候选集。
3. 对候选集使用 `compare_stocks` 做本地多指标复核和两两淘汰。
4. 最终按上限保留龙头。

**推荐查询模板**（按场景选择）：

| 目标 | 查询模板 | 说明 |
|------|----------|------|
| 通用龙头 | `<板块名> 龙头股` | 问财内置龙头识别，适合行业/概念 |
| 收入规模龙头 | `<板块名>概念股 营业收入前30` | 板块相关收入规模最大 |
| 收入成长龙头 | `<板块名>概念股 近两年营收增长前30` | 高成长标的 |
| 综合精选 | `<板块名>概念股 市值前30 营业收入 近两年营收增长` | 同时获取市值、收入、增长 |
| 热度参考 | `<板块名>概念股 个股热度` | 问财个股热度字段，反映市场关注度 |
| 行业成分股 | `<板块名>行业股票 市值前50` | 获取行业成分股并排序 |
| 概念成分股 | `<概念名>概念股 市值前50` | 获取概念成分股并排序 |

示例：
```
"白酒 龙头股"
"固态电池概念股 市值前30 营业收入 近两年营收增长"
"储能概念股 营业收入 近两年营收增长"
"固态电池概念股 人气排名"
```

**精选规则**：
- 问财返回结果往往已经按龙头特征排序，但仍需通过 `compare_stocks` 和财务数据复核以下指标：
  1. **板块相关营业收入**：优先看与板块直接相关的收入规模（如固态电池、储能系统收入），排除主营不相关业务的收入干扰。若财报未直接披露板块收入，可通过主营产品/行业分部收入推断。
  2. **收入成长性**：若当前板块相关收入不大，则看最近两年营业收入增长率，优先选择高增长标的。
  3. **情绪/关注度**：优先选择同板块内关注度/人气排名靠前的股票（如东方财富人气榜、问财热度、换手率等综合反映市场关注度的指标）。排名处于同板块前 50% 为佳。
  4. **技术趋势/近期涨幅**：作为辅助参考，不设置硬性前 30% 门槛；重点排除股价趋势明显弱于板块多数股票的标的。
  5. 市值是否明显领先
  6. 换手率/成交额是否具备市场关注度
- 若问财返回的前 N 只股票中，某只在至少 **3个核心指标** 上明显弱于同板块另一只，则淘汰。
- **不使用 PE/PB 作为淘汰依据**。
- **不设置短期涨幅排名的硬性淘汰线**，避免单日波动导致结果不稳定。

### 模式二：本地数据库模式

当问财不可用时，使用本地 `market.db` 数据：
- 行业成分股：`get_industry_stocks`（`standard` 默认 `sw_l1`，可指定 `sw_l2`/`sw_l3`）
- 概念成分股：`get_concept_stocks`
- 本地筛选：`screen_stocks` / `advanced_screen`，`scope` 可设为 `industry:行业名` 或 `concept:概念名`

## 龙头股筛选指标（按重要性排序）

对板块内每只股票，优先获取以下指标：

1. **板块相关营业收入**：与板块直接相关的收入规模。优先使用财报中披露的分产品/分行业收入，排除与板块无关的业务收入。
2. **收入成长性**：最近两年营业收入同比增长率。当前收入不大但增速高的标的，可作为高成长龙头候选。
3. **情绪/关注度**：同板块内的人气/关注度排名（如前 50%），优先使用问财 `个股热度` 字段；也可用换手率、成交额等近似反映。
4. **市值（total_cap）**：越大越具备龙头特征。
5. **流动性（turnover）**：换手率越高，市场关注度越高。
6. **资金流向**：近5日/10日主力净流入，越大越好。
7. **技术趋势/技术强度**：近期股价趋势、是否位于主要均线之上，仅作辅助参考，不设置硬性涨幅排名门槛。

**不参考 PE/PB**：龙头筛选不将 PE/PB 作为核心指标或淘汰依据。
**不设置短期涨幅硬性门槛**：避免单日波动导致结果不稳定。

## 龙头分类

为兼顾稳健龙头与成长龙头，每只板块最终股票池可分为两类，每类最多保留 **3只**，整体不超过 **6只**。

### 类型一：市值收入型龙头

**核心标准**：板块相关营业收入大、市值领先。

- 优先选择板块相关收入排名前位的标的。
- 市值作为辅助验证，确保龙头具备一定市场体量。
- 数量：最多 3 只。

### 类型二：高成长+高关注度龙头

**核心标准**：收入成长性高、市场关注度高。

- 优先选择最近两年营收增长率高的标的。
- 使用 `个股热度` 或换手率/成交额确认市场关注度处于同板块前 50%。
- 当前收入规模可小于类型一，但成长斜率需明显领先。
- 数量：最多 3 只。

**合并规则**：两类结果合并去重后作为最终龙头股票池。若某只股票同时满足两类标准，只保留一次。

## 两两淘汰规则

1. **候选集**：先按板块相关收入/市值+关注度粗筛，将板块股票压缩到最多 **30只**。若板块本身 ≤30只，全部进入。
2. **分类排序**：
   - 类型一按板块相关收入降序取前 3。
   - 类型二按营收增长率降序（在热度前 50% 内）取前 3。
3. **对比方式（tie-breaking）**：当同一类内候选核心指标接近（差距 < 20%）时，使用 `compare_stocks` 对比价格/流动性，或用 iwencai 数据对比关注度，进行 pairwise 淘汰。
4. **淘汰条件**：一只股票在 **板块相关收入、收入成长性、关注度、市值、流动性** 这5个核心指标中，至少有 **3个** 明显弱于另一只股票，则被淘汰。
5. **禁止行为**：
   - 不得使用 PE/PB 作为淘汰依据。
   - 不得仅因短期单日涨跌幅淘汰股票。
   - 不得设置短期涨幅排名的硬性淘汰线。
   - pairwise 不得让市值、热度等次要指标显著 override 收入/增速等核心指标。
   - 不得让龙头数量超过上限。

## 龙头数量上限

最终保留的龙头总数 `L` 满足：

```
1 ≤ L ≤ 6
```

按两类分别选取时：
- 类型一（市值收入型）：最多 3 只
- 类型二（高成长+高关注度）：最多 3 只
- 两类合并去重后总数不超过 6 只

若板块成分股极少（如 N ≤ 10），可适当降低总数，但两类划分思路不变。

## 输出格式

返回一个结构化表格，包含：

| 代码 | 名称 | 板块 | 类型 | 板块相关收入(亿) | 近两年营收增速 | 关注度/人气排名 | 市值(亿) | 入选理由 |
|------|------|------|------|------------------|----------------|-----------------|----------|----------|

同时调用 `manage_stock_pool` 创建股票池，命名规则：
```
<板块名>_龙头_<YYYYMMDD>
```
例如：`白酒_龙头_20260701`

## 完整工作流

### Step 1：解析用户意图

确认：
- 板块类型：行业 / 子行业 / 概念
- 板块名称或股票池ID
- 是否使用问财（默认尝试，失败则 fallback 本地）

### Step 2：问财直接初筛（推荐）

默认使用 `iwencai_screen` 直接查询板块龙头股：
```json
{"query": "<板块名> 龙头股", "mode": "stock", "limit": 30}
```

若返回数量不足或需要更严格排序，可换用：
```json
{"query": "<板块名> 市值前30 主力净流入前10", "mode": "stock", "limit": 30}
```

对概念板块：
```json
{"query": "<概念名>概念股 市值前30 20日涨幅前10", "mode": "stock", "limit": 30}
```

**iwencai 返回的字段通常已包含**：股票代码、名称、最新价、涨跌幅、市值、换手率等。后续需补充查询：**营业收入**、**近两年营收增长率**、**20日涨幅**。

**本地模式**（问财失败时 fallback）：
- 行业：`get_industry_stocks`，`industry` 填行业名，`standard` 默认 `sw_l1`
- 概念：`get_concept_stocks`，`concept` 填概念名
- 然后用本地筛选/排序压缩到30只候选

### Step 3：精选候选集

取 Step 2 返回的前 **30只** 作为精选候选集（若板块本身 ≤30只，则全部进入）。

**获取财务数据**：
使用 `iwencai_screen` 查询候选股的收入与增长：
```json
{"query": "<板块名>概念股 营业收入 近两年营收增长", "mode": "stock", "limit": 30}
```

或用更具体的问财查询：
```json
{"query": "<板块名>概念股 2024年营收 2023年营收 营收增长率", "mode": "stock", "limit": 30}
```

**获取情绪/关注度数据**：
使用 `iwencai_screen` 查询问财 `个股热度` 字段：
```json
{"query": "<板块名>概念股 市值前30 个股热度", "mode": "stock", "limit": 30}
```

也可同时获取收入、增长与热度：
```json
{"query": "<板块名>概念股 市值前30 营业收入 近两年营收增长 个股热度", "mode": "stock", "limit": 30}
```

`个股热度[YYYYMMDD]` 为问财提供的个股关注度/人气指标，数值越高代表市场关注度越高。将其换算为同板块内排名，前 50% 为佳，但不做硬性淘汰线，仅作为 pairwise 对比指标之一。

若问财热度字段不可用，可用 **换手率/成交额** 作为关注度的代理指标。

**复核技术面**：
使用 `compare_stocks` 对候选集分批复核每只股票的：
- 最新价、涨跌幅
- 市值（total_cap）
- 换手率（turnover）

近期涨幅仅作辅助参考，不设置硬性排名门槛。

### Step 4：分类精选龙头

将候选股票分为两类分别精选，每类最多保留 3 只。分类内部以核心指标排序为主，pairwise 仅用于指标接近时的 tie-breaking。

**类型一：市值收入型龙头**
- 按板块相关收入降序排列，取前 3 名。
- 若收入接近（差距 < 20%），可辅以市值、关注度做 pairwise  tie-breaking。
- 保留最多 3 只收入规模领先的龙头。

**类型二：高成长+高关注度龙头**
- 先筛选 `个股热度` 排名处于同板块前 50% 的候选。
- 再按营收增长率降序排列，取前 3 名。
- 若增速接近（差距 < 20%），可辅以热度排名、板块相关收入做 pairwise  tie-breaking。
- 保留最多 3 只高成长且受市场关注的龙头。

**合并**：两类结果去重合并。若合并后总数超过 6 只，按板块相关收入+关注度综合排序截取至 6 只；若不足 6 只，按实际结果输出。

### Step 5：两两对比淘汰（tie-breaking 用）

在每一类内部，若候选数量超过上限且核心指标接近，则进行 pairwise 对比：
- 每轮对比 2–5 只指标接近的股票。
- 根据5个核心指标（板块相关收入、收入成长性、关注度、市值、流动性），淘汰明显弱势者。
- **注意**：pairwise 不得让市值、热度等次要指标显著 override 收入/增速等核心指标。

### Step 6：保存结果

调用 `manage_stock_pool`：
```json
{
  "action": "create",
  "name": "<板块名>_龙头_<YYYYMMDD>",
  "description": "<板块名> 板块龙头选择结果，共 <N> 只成分股，选出 <L> 只龙头",
  "codes": [
    {"code": "600519", "market": 1, "name": "贵州茅台"},
    ...
  ]
}
```

### Step 7：输出报告

输出最终龙头表格及保存的股票池ID/名称。

## 错误处理与降级

1. **问财失败**：提示用户检查 `IWENCAI_API_KEY`，并自动切换到本地数据库模式。
2. **本地数据缺失**：如果行业/概念成分股为空，提示用户先同步数据（`--sync-sectors`、`--sync-concepts`）。
3. **某只股票指标缺失**：跳过该指标参与对比；若缺失指标过多，降低该股票在对比中的权重，但不直接淘汰。
4. **板块股票不足5只**：直接按规则上限选取，不做复杂对比，报告中注明"成分股较少，结果参考性有限"。

## 示例

### 示例1：选出白酒行业龙头

用户："选出白酒行业的龙头"

执行步骤：
1. 直接问财：`{"query": "白酒 龙头股", "mode": "stock", "limit": 30}`
2. 取返回的前10-20只作为候选（白酒行业成分股较少）。
3. 查询收入与增长：`{"query": "白酒概念股 营业收入 近两年营收增长", "mode": "stock", "limit": 30}`
4. 尝试查询关注度：`{"query": "白酒概念股 人气排名", "mode": "stock", "limit": 30}`
5. 使用 `compare_stocks` 复核市值、流动性。
6. 分类精选：
   - 类型一（市值收入型）：按板块相关收入选前 1–2 只。
   - 类型二（高成长+高关注度）：按营收增长+热度选前 1–2 只。
7. 合并去重，每类最多3只，总数最多6只；白酒行业成分股较少，实际可取2–4只。
8. 保存为 `白酒_龙头_20260701`。
9. 输出表格及入选理由。

### 示例2：选出人工智能概念龙头

用户："人工智能概念龙头股"

执行步骤：
1. 直接问财：`{"query": "人工智能 龙头股", "mode": "stock", "limit": 30}`
2. 若结果偏少，改用：`{"query": "人工智能概念股 市值前30 营业收入", "mode": "stock", "limit": 30}`
3. 概念成分股通常较多，候选集压缩到30只。
4. 查询营收与增长：`{"query": "人工智能概念股 营业收入 近两年营收增长", "mode": "stock", "limit": 30}`
5. 尝试查询关注度：`{"query": "人工智能概念股 人气排名", "mode": "stock", "limit": 30}`
6. 每类最多3只，总数最多6只。
7. 分类精选：类型一最多3只，类型二最多3只，合并去重。
8. 保存为 `人工智能_龙头_20260701`。

### 示例3：对自选股股池按行业分组选龙头

用户："对自选股股池53号按行业分组，每组选龙头"

执行步骤：
1. 用 `manage_stock_pool` 查询股池53内容。
2. 对每只自选股调用 `get_stock_industries` 获取其行业。
3. 按行业分组。
4. 对每个行业组执行上述龙头选择流程。
5. 将所有组的结果合并为一个新的股票池：`自选股53_行业龙头_20260701`。

## 注意事项

- 所有数据来源需在最终报告中标注：问财数据标注"数据来源：同花顺问财"，本地数据标注"数据来源：trading-agent 本地数据库"。
- 本技能仅为辅助分析，不构成投资建议。
- 若用户未指定具体板块，先调用 `analyze_market_theme` 或 `iwencai_screen`（`mode: plate`）获取当前热门板块，再请用户选择。
